# Ticket-Dokumentation (verbindlich)

Jeder Lab-Agent dokumentiert Arbeit **im GitHub-Ticketsystem**, nicht nur in Chat oder Outbox.

## Regeln
1. Jede abgeschlossene Lab-Rolle hinterlässt Spur an einem Issue: neuer Issue **oder** Kommentar an bestehendem Issue (Launch #2–#5, Lab-Meta, Build-Ticket).
2. Outbox/Reports bleiben Pflichtartefakte; Issues sind die **menschliche** Arbeitsspur und Querverweis.
3. Kommentar-Minimum: Rolle, Iteration/Phase, Link auf Outbox/Report-Pfad, Status (done|blocked|partial), nächster Schritt.
4. Stories/ACs weiter nur in Issues (nicht Chat-Dumps).
5. Meta-Steward prüft stichprobenartig, ob Ticket-Spuren fehlen.

## Labels (Vorschlag)
- `lab` — Lab-Prozess
- `lab-meta` — Setup/Workflow-Optimierung
- `lab-build` — Copilot Build (Template)
- bestehende: `play-store`, `closed-testing`, …
